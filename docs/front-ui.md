## 1. 全局设计约定

### 1.1 通用交互规则

| 规则 | 说明 | 依据 |
| --- | --- | --- |
| 提交期间禁用按钮 | 保存/删除按钮进入 `loading` 且 `disabled`，防止重复提交 | spec §11、E-16 |
| 删除二次确认 | 账单、分类删除均弹出确认框 | spec §7.3、§7.5、AC-05 |
| 类型联动 | 账单表单中切换"收入/支出"后，分类下拉框**重新加载并清空**已选分类 | spec §7.4、AC-03 |
| 写后刷新 | 新增/编辑/删除成功后，刷新当前列表与看板数据 | AC-01、AC-14 |
| 前端即时校验 | 表单在提交前做与后端一致的本地校验（金额、日期、备注、必填），错误就地提示 | E-01、E-06、E-08、AC-02 |
| 空值展示 | 备注为空显示 `—`，不显示 `null` | — |

### 1.2 请求与错误处理（统一拦截器）

所有请求经统一 axios 实例，按 `api-design §2.1` 的统一结构 `{code, message, data}` 处理：

- `code === 0` → 取 `data` 交付业务；
- `code !== 0` → 抛出携带 `code` / `message` 的错误，由页面决定展示位置；
- 网络异常 / 超时（E-15）→ 全局提示"网络异常，请重试"；
- `1999` → 全局提示"服务器内部错误"。

### 1.3 错误码 → 前端提示位置对照（严格对齐 `api-design §2.2`）

| code | 标准 message | 前端展示位置 |
| --- | --- | --- |
| 1001 | `参数不合法` | 表单字段级错误提示 |
| 1001 | `备注长度超限` | **备注**字段下方 |
| 1001 | `分类名称不合法` | **分类名称**字段下方 |
| 1002 | `金额不合法` | **金额**字段下方 |
| 1003 | `金额超出允许范围` | **金额**字段下方 |
| 1004 | `日期不合法` | **日期**字段下方 |
| 1005 | `月份不合法` | 月份选择器旁（前端一般不会触发） |
| 1006 | `分类类型与收支类型不一致` | 表单顶部提示 + 重置分类下拉 |
| 1007 | `分类不存在` | 提示后刷新分类列表并重置分类选择 |
| 1008 | `记录不存在` | 提示后关闭弹窗并刷新列表 |
| 1009 | `该分类已存在` | **分类名称**字段下方 |
| 1010 | `该分类下存在记录，无法删除` | 提示（确认框不关闭），引导用户先去账单管理处理 |
| 1999 | `服务器内部错误` | 全局消息条 |

### 1.4 金额、日期与月份展示格式（spec §7.7）

| 项 | 格式 | 示例 |
| --- | --- | --- |
| 收入/支出/分类金额 | `¥` + 千分位 + 2 位小数 | `¥1,234.56` |
| 负结余 | `-¥` + 千分位 + 2 位小数 | `-¥200.00` |
| 结余为正/零 | `¥` + 千分位 + 2 位小数 | `¥7,354.17` / `¥0.00` |
| 占比 | 2 位小数 + `%`，**直接使用后端 `percentage`** | `58.30%` |
| 日期 | `YYYY-MM-DD` | `2026-10-05` |
| 月份 | `YYYY-MM` | `2026-10` |

> **精度来源**：接口返回的是 JSON number（如 `12500.0`、`58.3`），尾零由前端 `toFixed(2)` 补足展示；前端**不做任何金额重算**。
> **饼图口径**：Chart.js 直接消费后端 `percentage`，不自行按金额求百分比（spec §6.3、AC-12）。

### 1.5 前端模块划分（对应 architecture.md 前端分层）

| 层 | 内容 |
| --- | --- |
| `views/` | `DashboardView`（看板）、`TransactionsView`（账单管理）、`CategoriesView`（分类管理） |
| `components/` | 见 §5 组件清单 |
| `api/` | `http.js`（axios 实例 + 拦截器）、`transactions.js`、`categories.js`、`reports.js` |
| `router/` | 上述 3 条路由 |
| `utils/` | 金额格式化、日期/月份工具、错误码文案映射 |
| 状态管理 | MVP **不使用 Pinia**，各页面用局部状态；分类列表在页面内按需加载 |

> **重要**：`GET /api/transactions` 的响应**只返回 `category_id`，不返回 `category_name`**（api-design §3.1）。因此账单表格需先加载 `GET /api/categories` 建立 `id → name` 映射后再渲染分类列。报表接口自带 `category_name`，无需映射。

## 2. 页面一：首页数据看板

### 2.1 页面布局（ASCII）

```

│  个人记账本        [数据看板]  [ 账单管理 ]  [ 分类管理 ]                       │ ← 顶部导航
├──────────────────────────────────────────────────────────────────────────────┤
│  ◀   2026-10    ▶         或  [ 2026-10  ▾ ]                    （月份切换区） │
├──────────────────────────────────────────────────────────────────────────────┤
│  ┌────────────────────┐  ┌────────────────────┐  ┌────────────────────┐      │
│  │ 本月收入            │  │ 本月支出            │  │ 本月结余            │      │
│  │ ¥12,500.00         │  │ ¥5,145.83          │  │ ¥7,354.17          │      │ ← 汇总卡片区
│  │ (绿色)              │  │ (红色)              │  │ (正绿 / 负红)        │      │
│  └────────────────────┘  └────────────────────┘  └────────────────────┘      │
├──────────────────────────────────────────────────────────────────────────────┤
│  支出分类占比                                                                  │
│  ┌───────────────────────────┐   ┌─────────────────────────────────────────┐ │
│  │                           │   │ ● 居住      ¥3,000.00        58.30%     │ │
│  │        ( 饼  图 )          │   │ ● 购物      ¥2,100.00        40.81%     │ │ ← 饼图 + 明细
│  │        Chart.js           │   │ ● 餐饮      ¥33.33            0.65%     │ │
│  │                           │   │ ● 交通      ¥12.50            0.24%     │ │
│  └───────────────────────────┘   └─────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 区域说明

| 区域 | 内容 | 数据来源 | 说明 |
| --- | --- | --- | --- |
| 顶部导航 | 3 个页面入口，当前页高亮 | 前端路由 | 全局组件，3 个页面共用 |
| 月份切换区 | `◀` 上一月 / `▶` 下一月 / 月份选择器 | 前端状态 | 切换后重新请求报表；**不允许选择晚于当前月的月份**（业务上无数据） |
| 汇总卡片区 | 收入、支出、结余 3 张卡片 | `total_income` / `total_expense` / `balance` | 结余 = 收入 − 支出（后端已算好，前端不重算）；负值按 §1.4 格式化为 `-¥200.00` 并标红（AC-22） |
| 饼图区 | 支出分类占比环形/饼图 | `expense_by_category[].percentage` | **直接使用后端 `percentage`**，前端不重算（AC-12）；扇区标签显示 `category_name` |
| 分类明细区 | 图例 + 金额 + 占比列表 | `expense_by_category` | 顺序与后端一致（按 `amount` 降序），前端**不再排序** |

### 2.3 按钮与交互

| 元素 | 行为 |
| --- | --- |
| `◀` / `▶` | 月份 ±1 个月，跨年自动进位（如 `2025-12` ◀ ▶ `2026-01`），切换后重新拉取报表 |
| 月份选择器 | 选中即刷新；仅允许 `YYYY-MM`，上限为当前月 |
| 卡片 / 明细行 | 只读，无点击行为（MVP） |

### 2.4 空数据状态

判定条件与展示**严格取自 api-design §3.8 的前端空状态判定表**：

| 条件 | 卡片区 | 饼图区 | 分类明细区 |
| --- | --- | --- | --- |
| `total_income == 0 且 total_expense == 0` | 三张卡片均 `¥0.00` | 居中显示 **"本月暂无数据"** | 隐藏（或显示空列表） |
| `total_income > 0 且 total_expense == 0` | 收入 `>¥0`、支出 `¥0.00`、结余 `=收入` | 居中显示 **"本月暂无支出数据"** | 隐藏 |
| `total_expense > 0` | 正常数值 | 正常饼图 | 正常列表 |

```
空状态（该月无任何记录）
┌───────────────────────────┐
│                           │
│      本月暂无数据          │   ← 图标 + 文案，居中
│                           │
└───────────────────────────┘

空状态（有收入、无支出）
┌───────────────────────────┐
│                           │
│    本月暂无支出数据         │
│                           │
└───────────────────────────┘
```

> 空数据时接口返回 `code 0 / HTTP 200`（E-13），前端**不得当作错误处理**。

## 3. 页面二：账单管理

### 3.1 页面布局（ASCII）

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  个人记账本        [ 数据看板 ]  [账单管理]  [ 分类管理 ]                    │
├──────────────────────────────────────────────────────────────────────────────┤
│  月份 [2026-10 ▾]   类型 [全部 ▾]   分类 [全部 ▾]      [重置]   [＋ 新增账单]  │ ← 筛选区
├──────────────────────────────────────────────────────────────────────────────┤
│   日期          类型     分类      金额          备注            操作          │
│  ──────────────────────────────────────────────────────────────────────────  │
│   2026-10-05    支出     餐饮     ¥33.33        午餐        [编辑] [删除]     │
│   2026-10-04    收入     兼职     ¥500.00       兼职收入    [编辑] [删除]     │
│   2026-10-03    支出     购物     ¥2,100.00     日用品      [编辑] [删除]     │
│   2026-10-02    支出     交通     ¥12.50        地铁        [编辑] [删除]     │
│  ──────────────────────────────────────────────────────────────────────────  │
│                              共 4 条记录                                       │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 区域说明

| 区域 | 内容 | 数据来源 |
| --- | --- | --- |
| 筛选区 | 月份、类型、分类 3 个筛选器 + 重置 + 新增按钮 | `month` / `type` / `category_id` 查询参数（api-design §3.1） |
| 表格区 | 日期、类型、分类、金额、备注、操作 | `GET /api/transactions` |
| 统计行 | 当前列表条数（由前端按数组长度计算，非接口字段） | 前端 Local |

### 3.3 筛选区（可选）

| 控件 | 取值 | 行为 |
| --- | --- | --- |
| 月份 | `YYYY-MM`，默认**当前月** | 变更即重新请求 |
| 类型 | `全部` / `收入` / `支出` | 选具体类型时传 `type=income\|expense`；`全部` 时不传该参数 |
| 分类 | `全部` / 各分类名称 | 随类型联动：选了类型后只列出该类型的分类；选 `全部` 类型时列出全部分类 |
| `重置` | — | 恢复为 月份=当前月、类型=全部、分类=全部 |
| `＋ 新增账单` | — | 打开新增弹窗 |

> **互斥筛选语义**：`type` 与 `category_id` 可同时传入。当所选分类的类型与所选 `type` 矛盾时，接口返回 `HTTP 200 + data: []`（AC-27），**不是错误**，前端应展示"无匹配结果"空态而非报错。
> **筛选不加分页**：API 未定义分页参数，MVP 一次性渲染当前筛选结果（当月数据量级小）。

### 3.4 表格列定义

| 列 | 字段 | 渲染规则 |
| --- | --- | --- |
| 日期 | `date` | `YYYY-MM-DD` 原样显示 |
| 类型 | `type` | `income` → 标签"收入"（绿）；`expense` → 标签"支出"（红） |
| 分类 | `category_id` | **经 `id → name` 映射后显示**（接口不返回 `category_name`） |
| 金额 | `amount` | 按 §1.4 格式化为 `¥1,234.56` |
| 备注 | `note` | 为空显示 `—`；过长省略号 + 悬浮完整内容 |
| 操作 | — | `[编辑]` `[删除]` 两个文字按钮 |

> 排序由后端给定（`date DESC, id DESC`，R-12），前端**不再二次排序**（AC-21）。

### 3.5 新增 / 编辑弹窗（ASCII）

新增与编辑**共用同一个弹窗组件**，仅标题与初始值不同。

```
┌────────────────────────────────────────────────────┐
│  新增账单                                      [×] │
├────────────────────────────────────────────────────┤
│  类型 *      ( • ) 支出    (   ) 收入               │ ← 单选，默认"支出"
│                                                    │
│  金额 *      [   33.33                  ] 元        │ ← 数字框，前缀/后缀
│              ⚠ 金额必须大于 0，最多 2 位小数         │ ← 校验错误就地提示
│                                                    │
│  分类 *      [ 餐饮                    ▾ ]          │ ← 下拉，按类型过滤
│                                                    │
│  日期 *      [ 2026-10-05              📅 ]         │ ← 日期选择器，范围受限
│                                                    │
│  备注        [ 午餐                            ]    │ ← 文本框
│              ( 2 / 100 )                            │ ← 码点计数
├────────────────────────────────────────────────────┤
│                            [ 取消 ]   [ 保存 ]      │ ← 保存提交期间禁用
└────────────────────────────────────────────────────┘
```

**表单字段与校验（与 spec §5.1、api-design §2.4 完全一致）**

| 字段 | 控件 | 必填 | 前端校验（提交前） | 后端错误码 |
| --- | --- | --- | --- | --- |
| `type` | 单选（收入/支出） | 是 | 默认"支出"，必选 | 1001 |
| `amount` | 数字输入框（单位：元） | 是 | `> 0`；`≤ 99,999,999.99`；最多 2 位小数 | 1002 / 1003 |
| `category_id` | 下拉框（按 `type` 联动过滤） | 是 | 必须选中；切换类型后自动清空重选 | 1007 / 1006 |
| `date` | 日期选择器 | 是 | 严格 `YYYY-MM-DD`；下限 `2000-01-01`；上限"今天" | 1004 |
| `note` | 文本框 | 否 | ≤ 100 个 Unicode 码点，超出禁止输入 | 1001 / `备注长度超限` |

**弹窗按钮行为**

| 按钮 | 行为 |
| --- | --- |
| `取消` / `[×]` | 关闭弹窗，丢弃未保存内容（若已修改，可加二次确认，MVP 可选） |
| `保存` | 关闭前先做本地校验 → 通过后调 `POST`（新增）或 `PUT /{id}`（编辑）；**提交期间按钮 `loading` + `disabled`**（E-16） |
| 保存成功 | 关闭弹窗 → 刷新列表 → 提示"保存成功" |
| 保存失败 | 弹窗**保持打开**，按 §1.3 将 message 定位到对应字段 |

**编辑态差异**：点击 `[编辑]` 时以该行数据回填表单（`amount` 反格式化去千分位；`date` 保持字符串），标题改为"编辑账单"，保存改用 `PUT /api/transactions/{id}`（全量覆盖，校验与新增完全一致，AC-24）。

### 3.6 删除确认

│                                            │
│  确认删除该记录？                            │

### 3.7 空数据状态

需区分**两种不同空态**（二者接口都返回 200）：

| 场景 | 判定 | 表格区展示 |
| --- | --- | --- |
| 该月确实无账单 | 无筛选（仅月份）且 `data == []` | **"本月暂无账单记录"** + `[＋ 记一笔]` 引导按钮 |
| 筛选后无匹配 | 存在类型/分类筛选且 `data == []` | **"没有符合条件的记录"** + `[重置筛选]` 按钮 |

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│                本月暂无账单记录                        │
│                                                      │
│                  [ ＋ 记一笔 ]                        │
│                                                      │
└──────────────────────────────────────────────────────┘
```

> 注意：筛选矛盾（AC-27）属第二种空态，**不得**展示为错误或网络异常。

| --- | --- | --- |
| 操作区 | `＋ 新增分类` 按钮 | — |
| 分组区 | 按收入/支出两组展示，每组标题带数量 | `GET /api/categories`（一次取回全部，前端按 `type` 分组） |
| 列表项 | 分类名称 + `删除` 按钮 | `id` / `name` / `type` |

> **分组顺序**：接口返回顺序为 `type` 升序、`id` 升序（api-design §2.5），即 **`expense` 组在前、`income` 组在后**。前端按此顺序直接渲染两个分组，不重排（AC-07 要求"类型清晰可见"）。
> **不展示 `id`**：`id`、`created_at` 均为内部字段，UI 不显示（api-design §3.5）。
> **MVP 不支持重命名**：spec §3.1 明确"分类编辑/重命名不属于 MVP"，故列表项只有一个 `删除` 操作。

### 4.3 新增分类弹窗（ASCII）

```
┌────────────────────────────────────────────────────┐
│  新增分类                                      [×] │
├────────────────────────────────────────────────────┤
│  类型 *      (   ) 支出    ( • ) 收入               │ ← 单选，默认"支出"
│                                                    │
│  名称 *      [ 宠物                             ]   │ ← 文本框
│              ( 2 / 20 )                             │ ← 码点计数
│              ⚠ 分类名称不合法                        │ ← 校验错误就地提示
├────────────────────────────────────────────────────┤
│                            [ 取消 ]   [ 保存 ]      │
└────────────────────────────────────────────────────┘
```

**表单字段与校验（spec §5.2）**

| 字段 | 控件 | 必填 | 前端校验 | 后端错误码 |
| --- | --- | --- | --- | --- |
| `type` | 单选（收入/支出） | 是 | 默认"支出" | 1001 |
| `name` | 文本框 | 是 | 去首尾空格后 1–20 个 Unicode 码点；空/纯空格不可提交 | 1001 / `分类名称不合法` |

| 结果 | 行为 |
| --- | --- |
| 成功 | 关闭弹窗 → 刷新分组列表 → 提示"新增成功"（AC-10：该分类立即出现在账单表单下拉中） |
| `1009` 该分类已存在 | 弹窗保持打开，`名称`字段下方提示"该分类已存在" |
| `1001` 分类名称不合法 | `名称`字段下方提示"分类名称不合法" |

> **重名判定范围**：同一 `type` 内重名才被拒绝；不同类型下同名允许（如"宠物"可同时存在于收入与支出）。

### 4.4 删除确认与失败处理

```
┌────────────────────────────────────────────┐
│  提示                                       │
│                                            │
│  确认删除分类「餐饮」？                       │
│                                            │
│                    [ 取消 ]   [ 确定删除 ]   │
└────────────────────────────────────────────┘
```

| 结果 | 行为 |
| --- | --- |
| 成功（无账单引用） | 关闭确认框 → 刷新分组 → 提示"删除成功" |
| `1010` 被账单引用 | 关闭确认框 → 提示 **"该分类下存在记录，无法删除"**，并可引导"前往账单管理处理"（AC-09） |
| `1007` 分类不存在 | 关闭确认框 → 提示"分类不存在" → 刷新分组（AC-25） |
| 取消 | 关闭确认框，不做任何修改 |

> **不显示引用条数**：接口不返回计数（spec §7.5 R-04），前端文案固定为"该分类下存在记录，无法删除"，不得自行拼接"N 条记录"。

### 4.5 空数据状态

| 场景 | 展示 |
| --- | --- |
| 某分组无分类（理论上预置分类不会为空） | 该分组下显示"暂无收入分类" / "暂无支出分类" |
| 全部为空（异常情况，如库被清空） | 整页显示"暂无分类" + `[＋ 新增分类]` 引导 |
| 接口失败（1999 / 网络异常） | 错误提示 + `[重试]` 按钮，不显示为空态 |

```
┌──────────────────────────────────────────────┐
│             暂无分类                          │
│          [ ＋ 新增分类 ]                      │
└──────────────────────────────────────────────┘
```
