## 1. 范围与设计原则

### 1.1 本期新增

| 编号 | 功能 | 一句话目标 |
| --- | --- | --- |
| OF-1 | 预算提醒 | 用户按月份设置预算，看板展示本月支出与使用率，超支时弹窗警告 |
| OF-2 | 账单搜索 | 按日期范围、收支类型、分类、备注关键词查询历史账单 |
| OF-3 | 数据导出 | 将当前筛选结果一键导出为 Excel 可直接打开的 CSV |

### 1.2 设计原则

1. **最小改动**：预算新建独立表 `budgets`，不修改 `categories` / `transactions`；搜索复用现有 `GET /api/transactions`；导出纯前端完成，不新增后端接口。
2. **口径一致**：金额仍以整数「分」入库、接口返回「元」；月份/日期沿用 `Asia/Shanghai` 与既有校验。
3. **风格统一**：新增界面全部复用 Element Plus 组件与现有变量、间距、文案风格。
4. **校验双层**：前端即时提示 + 后端统一校验，错误码沿用既有 1001–1010 / 1999，不新增错误码。
5. **可回退**：不修改原表结构，删除新代码即可回到 MVP 行为；新表可单独删除。

## 2. 功能 OF-1：预算提醒

### 2.1 用户故事

- 作为用户，我可以为某个月设置预算金额，以便控制当月消费。
- 作为用户，我在看板能直接看到本月预算、已支出和预算使用率。
- 作为用户，当本月支出超过预算时，我进入看板会收到明确的超支警告。

### 2.2 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-1.1 | 预算以**月份**为维度，一个月最多一条记录，重复设置为覆盖更新 |
| BR-1.2 | 预算金额必须 > 0、最多 2 位小数、≤ 99,999,999.99 元 |
| BR-1.3 | 预算金额入库单位为「分」（INTEGER），与账单金额口径一致 |
| BR-1.4 | 月份缺省时使用业务时区（Asia/Shanghai）的当前月 |
| BR-1.5 | 「本月支出」取月度报表 `total_expense`，与看板卡片同源 |
| BR-1.6 | 超支判定：`total_expense > budget`（等于预算不算超支） |
| BR-1.7 | 超支提示按月份去重，同一月份在一次页面会话中只弹一次 |
| BR-1.8 | 未设置预算时，预算区域显示「未设置」，不触发超支判断 |
| BR-1.9 | 预算读取失败不影响看板收入/支出/结余与饼图展示 |

### 2.3 接口契约

**查询预算**

```
GET /api/budgets?month=YYYY-MM      # month 可省略，省略时为当前月
200 {"code":0,"message":"OK","data":{"month":"2026-10","amount":null}}
200 {"code":0,"message":"OK","data":{"month":"2026-10","amount":3000.0}}
```

**设置 / 覆盖预算**

```
PUT /api/budgets
{"month":"2026-10","amount":3000}
200 {"code":0,"message":"OK","data":{"month":"2026-10","amount":3000.0}}
```

### 2.4 校验与错误码

| 场景 | 前端行为 | 后端返回 |
| --- | --- | --- |
| 金额为空 / 非数字 / ≤ 0 / 超过 2 位小数 | 字段下方提示「预算金额不合法」，不发请求 | 1002 金额不合法（HTTP 400） |
| 金额 > 99,999,999.99 | 字段下方提示超出上限 | 1003 金额超出允许范围（HTTP 400） |
| 月份不是 `YYYY-MM` 或月份越界 | 前端月份为只读 | 1005 月份不合法（HTTP 400） |
| 月份格式合法但不存在记录 | 显示「未设置」 | 200 / `amount: null` |
| 数据库异常 | 提示保存失败，弹窗保持打开 | 1999 服务器内部错误（HTTP 500） |

### 2.5 页面要求（数据看板 `/`）

- 顶部新增预算条：`本月预算 ¥X` / `已支出 ¥Y` / `使用率 Z%`；未设置时显示「本月预算 未设置」与「设置预算」按钮。
- 已设置时按钮文案为「修改预算」，点击弹出设置弹窗（月份只读、金额输入）。
- 使用 `el-progress` 展示使用率；超支时进度条与数值使用危险色，并显示「已超支 ¥N」。
- 超支弹窗标题「预算超支提醒」，文案包含本月支出、预算与超支金额；提供「知道了」按钮关闭。

### 2.6 验收标准

| 编号 | 验收点 |
| --- | --- |
| AC-OF1-1 | 可设置当月预算，刷新页面后金额仍存在（持久化） |
| AC-OF1-2 | 再次设置同月预算为覆盖更新，不产生多条记录 |
| AC-OF1-3 | 未设置预算时接口返回 `amount: null`，页面显示「未设置」 |
| AC-OF1-4 | 本月支出 > 预算时进入看板弹出超支警告；同月只弹一次 |
| AC-OF1-5 | 本月支出 ≤ 预算时不弹窗 |
| AC-OF1-6 | 非法金额被拦截，返回 1002/1003；非法月份返回 1005 |
| AC-OF1-7 | 预算按月份隔离，切换月份读取对应月份预算 |

## 3. 功能 OF-2：账单搜索

### 3.1 用户故事

- 作为用户，我可以按日期范围查找某段时间的账单（可跨月）。
- 作为用户，我可以按备注关键词找到某笔消费。
- 作为用户，我可以组合收支类型与分类缩小结果范围，并看到筛选后的列表。

### 3.2 查询参数（在现有列表接口上扩展）

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `start_date` | `YYYY-MM-DD`，可选 | 起始日期（含） |
| `end_date` | `YYYY-MM-DD`，可选 | 结束日期（含） |
| `keyword` | string，可选，≤100 码点 | 备注模糊匹配，去首尾空格 |
| `type` | income / expense，可选 | 两种模式下都生效 |
| `category_id` | int，可选 | 两种模式下都生效，不校验分类是否存在 |
| `month` | `YYYY-MM`，可选 | **仅普通模式生效** |

### 3.3 模式规则

| 编号 | 规则 |
| --- | --- |
| BR-2.1 | 提供 `start_date` / `end_date` / `keyword` 任一非空参数即进入**搜索模式** |
| BR-2.2 | 搜索模式跨月查询，`month` 被忽略（前端有明确提示） |
| BR-2.3 | 未提供上述参数时为普通模式，按 `month`（缺省当前月）查询 |
| BR-2.4 | 日期两端均可只提供一端：只给开始 = 该日期及以后；只给结束 = 该日期及以前 |
| BR-2.5 | 开始日期晚于结束日期 → 1004「日期范围不合法」 |
| BR-2.6 | 关键词按字面量匹配，`%`、`_` 不作 SQL 通配符 |
| BR-2.7 | 结果排序固定 `date DESC, id DESC` |
| BR-2.8 | 无匹配结果返回 `200 / data: []`，不视为错误 |
| BR-2.9 | `type` 与 `category_id` 矛盾时返回空数组，不报错 |

### 3.4 接口示例

```
GET /api/transactions?start_date=2026-01-01&end_date=2026-03-31
GET /api/transactions?keyword=地铁
GET /api/transactions?keyword=午餐&type=expense&category_id=6
GET /api/transactions?start_date=2026-10-01
```

### 3.5 校验与错误码

| 场景 | 前端行为 | 后端返回 |
| --- | --- | --- |
| 开始日期晚于结束日期 | 提示「开始日期不能晚于结束日期」，不发请求 | 1004 日期范围不合法 |
| 日期格式非法 / 早于 2000-01-01 / 晚于今天 | 日期控件限制选择 | 1004 日期不合法 |
| 关键词超过 100 字 | 提示关键词过长 | 1001 关键词长度超限 |
| 无匹配结果 | 列表空状态「没有符合条件的记录」 | 200 / `[]` |

### 3.6 页面要求（账单管理 `/transactions`）

- 在原有筛选行下方新增搜索行：日期范围、备注关键词、「查询」「清除搜索」「导出 CSV」。
- 条件为草稿状态，点击「查询」或在关键词框回车才请求，避免频繁请求。
- 搜索模式显示提示：「当前为搜索模式：按日期范围 / 备注关键词跨月查询，月份选择不生效」。
- 「清除搜索」清空搜索条件并回到当前月份视图；「重置」同时清空原有类型/分类筛选。
- 列表底部展示「共 N 条记录」。

### 3.7 验收标准

| 编号 | 验收点 |
| --- | --- |
| AC-OF2-1 | 只输入关键词可查到备注包含该词的记录（跨月） |
| AC-OF2-2 | 日期范围可跨月筛选，结果包含两端日期 |
| AC-OF2-3 | 类型、分类可与搜索条件叠加生效 |
| AC-OF2-4 | 开始日期晚于结束日期被前端拦截，接口返回 1004 |
| AC-OF2-5 | 关键词 `%` / `_` 按字面量匹配 |
| AC-OF2-6 | 搜索模式忽略 `month`，清除后可恢复月份视图 |
| AC-OF2-7 | 无结果时展示空状态，不报错 |
| AC-OF2-8 | 原有月份筛选、类型筛选、新增/编辑/删除不受影响 |

## 4. 功能 OF-3：数据导出

### 4.1 用户故事

- 作为用户，我可以把当前筛选出的账单导出为 CSV，直接用 Excel 打开做二次分析。

### 4.2 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-3.1 | 导出范围为**当前列表可见结果**（月份视图或搜索结果） |
| BR-3.2 | 列固定：日期、类型、分类、金额(元)、备注 |
| BR-3.3 | 类型输出中文「收入 / 支出」；金额保留 2 位小数 |
| BR-3.4 | 文件编码 UTF-8 **带 BOM**，换行 CRLF，Excel 打开不乱码 |
| BR-3.5 | 单元格含逗号、引号、换行时按 CSV 规范用双引号包裹并转义 |
| BR-3.6 | 文件名 `账单_YYYY-MM-DD.csv` |
| BR-3.7 | 列表为空时按钮禁用；无数据不生成文件 |
| BR-3.8 | 导出在前端完成，不写数据库、不新增后端接口 |

### 4.3 异常处理

| 场景 | 行为 |
| --- | --- |
| 列表为空 | 按钮禁用并提示「当前没有可导出的记录」 |
| 浏览器不支持 Blob / 下载被拦截 | 提示导出失败，不影响页面数据 |
| 备注为空 | 输出空单元格 |
| 备注含换行 | 引号包裹，Excel 显示为单元格内换行 |

### 4.4 验收标准

| 编号 | 验收点 |
| --- | --- |
| AC-OF3-1 | 点击导出下载 CSV，文件名符合规则 |
| AC-OF3-2 | 导出条数与当前列表条数一致 |
| AC-OF3-3 | Excel 打开中文、金额、日期正常，无乱码/串列 |
| AC-OF3-4 | 备注含逗号/引号/换行的记录导出后仍完整 |
| AC-OF3-5 | 搜索结果导出与搜索条件一致 |
| AC-OF3-6 | 空列表时不可导出 |

## 5. 兼容性与非功能要求

| 编号 | 要求 |
| --- | --- |
| NF-1 | 原有 8 个 API 的路径、请求体、响应结构、错误码不变 |
| NF-2 | 原有前端页面路由与布局不变，新控件沿用现有组件与样式 |
| NF-3 | 新增接口沿用统一响应 `{code,message,data}` 与 `Asia/Shanghai` |
| NF-4 | 金额精度：元↔分转换使用 `ROUND_HALF_UP`，展示 2 位小数 |
| NF-5 | 数据库升级仅新增 `budgets` 表，可重复执行 SQL 脚本（IF NOT EXISTS） |
| NF-6 | 部署包同时包含后端代码、SQL 脚本与已构建前端产物 |

## 6. 明确不做（Out of Scope）

- 预算的分类维度、周期预算、预算历史趋势、超支邮件/推送。
- 搜索的模糊拼音、分词、全文索引、保存搜索条件。
- 导出 Excel 多 sheet、PDF、报表模板、定时导出。
- 用户账号、多用户数据隔离、云同步。
